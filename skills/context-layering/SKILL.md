# context-layering — 常時読み込みを軽くし、情報は失わない

## 目的

セッション開始時に毎回読み込まれるものを軽くする。何が読み込まれているかはプロジェクトごとに違うので、実態を調べて特定する。
プロジェクトの情報は減らさない。参照用ドキュメントへ整理して移し、常時側には「何がどこにあり、いつ読むか」を残す。

## 層の考え方

- **常時**: 毎回読まないと事故るもの(禁止事項、環境の罠、コマンド、合意事項、引き継ぎ点)と、参照への索引
- **参照**: その作業に着手した時に読めば足りる詳細
- **履歴**: 日付ごとの経緯。教訓を常時か参照へ転記してから移す

## 手順

1. **監査と報告(ここで必ず止まる)**: 常時読み込まれるファイルと量を示し、内容ごとに「常時に残す / 参照へ / 履歴へ」の
   振り分け案を、残す理由・移す先・読む契機とともに報告する。変更に必要なモデルを示し、現在より上位が必要なら
   切り替えてこのスキルを実行し直すよう求めて止まる。「整理不要」も正当な結論。ユーザーの判断を待つ。
2. **バックアップ**: 変更するファイルのバックアップをプロジェクト内に作る。
3. **参照・履歴への整理**: 内容は変えずに移す。索引には要約を書かず、場所と読む契機だけ書く。迷ったら移さず残す。
4. **CLAUDE.md は最後**: 現在の記述を台帳化し、新しい版を別ファイルに作り、全項目の行き先を照合してから差し替える。
5. **全体確認**: 変更したファイルをすべて通読し、移動元の内容が移動先に残っていることを確認して報告する。

## やらないこと

- 情報を削らない
- 何を移すかを勝手に確定しない(提案し、ユーザーが決める)
- コミット・push はしない
